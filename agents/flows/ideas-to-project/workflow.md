# Carry a selected idea into a project proposal

Authoring package only — not runnable. See the
[Shared execution contract](../README.md#runtime-boundary) for permissions, full commit markers,
failure recovery and future manual/scheduled execution. No live research or provider call occurs.

## Inputs and evidence

- Original idea/source and owner: `<original source links, IDs and responsible owner>`.
- Defaults: selected-document, explicit-baseline, product, project-proposal.
- Local destination declaration: `Plans/flows/ideas-to-project.md`.
- Source selection/provenance: `<actual supplied revisions, dates, audience and scope>`.
- Required sources: selected idea and actual selection record, original evidence rejected alternatives and unresolved questions, intended owner and project plan or feature destination.

Record source references, original wording, assumptions, objections and unknowns separately. For
missing mandatory evidence, block its dependent claim; preserve independent work and rejected
alternatives. A report/proposal is not validation, an owner decision or an action approval.

## Domain steps

### collect

Read the selected idea and its actual source selection record, evidence, rejected alternatives and unresolved questions. Preserve original IDs, source references and verbatim human history; do not infer selection from a ranking or rewrite old decisions.

### proposal

Draft the proposed project, plan or feature flow destination, owner, scope, acceptance and dependencies. Carry the original evidence/alternatives/questions into linked project context without renumbering, closing unresolved work or creating directories.

### handoff

Declare a proposed handoff to the named project owner for a deliberate next plan. This is inert route metadata: no root creation, configuration write, project initialization, task assignment or message send occurs. Missing selection/owner evidence blocks its dependent promotion claim.

## Approval boundary and outcome

Actual project/root creation, initialization, config/grant changes, plan edits, assignments and sends require their real authority plus a separate preview and explicit approval. A selected idea is not an administrator grant or approval of every implementation action.

The local brief/report is complete without a tracker. A declared handoff is data only, not a sent
request; no source changes, roots, projects, experiments or scheduled runs are created by this package.
